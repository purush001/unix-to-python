# Decisions

Each decision has a reason. Where two requirements conflicted, the priority order of the
build prompt decided (1 data protection, 2 honesty and correctness, 3 human control,
4 reliability, 5 observability, 6 cost and latency, 7 features). Decisions made without
asking are marked **assumption** and can be reversed.

| ID | Decision | Reason | Conflict resolved |
|---|---|---|---|
| D1 | Upgrade the existing code; do not rebuild. | The audit found the sanitizer, validators, pipeline, approval flow and secret handling already match the standards. Every gap was an addition. | — |
| D2 | `HONESTY_RULE` is one constant in `src/agents/prompts.ts`, included verbatim in all five system prompts (two agents, reviewer, rule writer, judge). A test fails if any prompt lacks it or breaks the fixed order. | S4. One constant cannot drift between prompts. | — |
| D3 | The "unknown" signal is structured: agents fill an `<unknown>` section, the reviewer uses code `REVIEW_UNKNOWN`, the rule writer returns `{"unknown": true}`, the judge answers `"unknown"` per criterion. Each becomes a warning code or is counted. | A signal in free text cannot be compared by code (S7). | — |
| D4 | The prompt version is the first 12 hex characters of the SHA-256 of the system prompt. It is written to every model-call span, log line, eval report and witness. | Any change to a prompt changes its version, with no manual step to forget. | — |
| D5 | Reviewer instructions moved from the user message to a system prompt. | Stable text first, so prompt caching applies, and one version hash covers the reviewer's rules. | — |
| D6 | A reply whose metadata does not match its zod schema is a transient error and is retried. Missing fields are never filled with defaults, and a review code outside the closed set is no longer dropped silently. | S7, and priority 2: a default `"medium"` risk or a dropped finding is a silent change. | Reliability (4) loses a little: stricter parsing can cost a retry. Honesty (2) wins. |
| D7 | Large code stays in tagged sections; `output_config.format` is not used. | S7 allows tagged sections so the script is never JSON-escaped. A JSON schema for the whole reply would force escaping of up to 200 KB of code. | — |
| D8 | An invented rule ID (`CHANGE_RULE_UNKNOWN`) is an **error**, so it triggers a repair. Allowed IDs are: guidance IDs given to the model, IDs the system prompt defines, issue codes, `reviewer-note` and `unspecified`. | S14 and `HONESTY_RULE` point 3. A reviewer approves from the change list; a made-up rule ID is a made-up reason. | Cost (6) loses: one more possible repair. Honesty (2) wins. |
| D9 | The system prompt is cache-marked with a 5-minute lifetime (`LLM_CACHE_TTL=5m`). | Assumption: DBAs convert in bursts. `1h` costs more to write; switch if the cache hit rate in the Status view stays low. | — |
| D10 | Effort stays `high` and is set explicitly. | The model's own default is `medium`. `high` is what the application ran on before; changing it needs an effort sweep on the real model, which has not been run. **Assumption.** | — |
| D11 | No named approver yet. `run.final` records the version and time only. | The application has one shared token and no identity. Fixing this means adding an identity provider (for example SSO), which is a design change for the owner to decide. S11 stays **partial**. | Human control (3) is not fully met; recorded, not hidden. |
| D12 | A run token budget (`MAX_RUN_TOKENS`, 1,500,000) stops further model calls. With no draft the run fails with `RUN_TOKEN_BUDGET_REACHED`; with a draft, repair and review are skipped and the reviewer is told. | S12 loop control. **Assumption** for the number: about ten calls at the largest input. | — |
| D13 | Spans are stored in the run record and served by `GET /api/runs/:id/trace`. They are not exported to an external tracing backend. | The run record is already the system of record and is written after every stage. An exporter needs a backend and a key the owner has not chosen. Attribute names follow the OpenTelemetry GenAI conventions so an exporter can be added without renaming. | Observability (5): no external backend yet; recorded. |
| D14 | Spans, logs and eval reports never hold script text, only hashes, counts, codes and IDs. | P7 and S15. Sanitized text is in the run record and the witness directory only. | — |
| D15 | An unknown price is reported as unknown (`costUsd: null`), never as 0. | Priority 2. A wrong cost is worse than a missing one. | — |
| D16 | Live judges run in the cron job on a deterministic sample (`LIVE_JUDGE_SAMPLE_PERCENT`, default 10) and never in a user request. | S15: a judge must never delay the user. Daily cadence follows the Vercel Hobby cron limit. | Latency (6) kept; freshness of judge scores is one day. |
| D17 | Alerts are evaluated once a day by the cleanup cron and on every `/api/status` call. The owner is `ALERT_OWNER`, default `OPS_EMAIL`. | No paging system exists; the application already sends operator mail. **Assumption**: daily is acceptable until volume grows. | Observability (5): not real-time; recorded. |
| D18 | The judge is never a gate on its own. Hard gates are code graders. The judge's mean score is compared with the baseline, and it is reported as "not calibrated" until 30 human labels exist. | S14. An uncalibrated judge must not block or pass a release alone. | — |
| D19 | The mock judge answers `"unknown"` for every criterion it cannot count. | A mock that answered "yes" would make the baseline claim faithfulness nobody measured. | — |
| D20 | Encoding tricks: invisible characters are removed; a token hiding `@` by percent-encoding or full-width characters, and a host with percent-encoded dots, is decoded and then sanitized. Both raise the warning `SANITIZE_OBFUSCATION_NORMALIZED`. The script is never decoded as a whole. | The new attack fixtures showed these forms leaked. A global decode would change legitimate text (`date +%Y%m%d`, `LIKE '%40%'`), which is a silent change of behaviour. | Data protection (1) wins over leaving the input byte-identical; the change is reported, not silent (2). |
| D21 | HTML, JSON, Python source and binary input are rejected as `INPUT_UNSUPPORTED_TYPE`, and the type selector cannot override that. A body not sent as `application/json` gets HTTP 415. | The classifier took all four for SQL because they contained SQL words. | — |
| D22 | Real-traffic samples are git-ignored by default. | **Assumption**: even sanitized scripts should be committed only after a person has read each one. | — |
| D23 | The eval baseline is committed per provider key (`mock`, or `real:<model>:<effort>`), without timestamps. It is updated only with `--update-baseline`, which refuses while any gate or fixture fails. | S14: a baseline that updates itself hides regressions. | — |
| D24 | Replay (`npm run replay`) uses mock storage, GitHub, memory and mail always, and the mock model unless `LLM_PROVIDER=anthropic` is set on purpose. | A debugging tool must never write to production or spend money by accident. | — |
